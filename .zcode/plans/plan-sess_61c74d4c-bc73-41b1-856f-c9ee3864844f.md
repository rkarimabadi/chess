### Key Design Decisions (Part 1)

| TQ | Decision | Why |
|---|---|---|
| Render mode | Interactive WebAssembly | Rich game interaction |
| Auth | Cookie + anti-forgery | Simplest for same-host, works with SignalR |
| Data access | EF Core | Dev speed; Dapper only if needed |
| Live state | In-memory dict + periodic DB snapshots | Fast during play, crash recovery |
| Client chess engine | Yes, lightweight mirror | UX latency hiding; server still authoritative |
| Production DB | PostgreSQL (when ready) | SQLite is dev-only per PRD |
| Hubs | 2 (GameHub + StaffHub) | Clean separation |
| Hub protocol | Strongly-typed | Compile-time safety |
